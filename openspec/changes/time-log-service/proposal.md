## Why

Сервиса учёта времени ещё нет: есть только описание. Один человек ведёт общий журнал из нескольких клиентов, в том числе из агента, и ему нужен документированный HTTP-контракт без собственного интерфейса журнала.

## What Changes

- Появляется сервис журнала: запись хранит идентификатор, начало, конец, наименование, теги и комментарий.
- Конец может быть пустым. Пустой конец значит, что дело ещё идёт. Таких записей одновременно может быть несколько.
- Клиенты с токеном создают, читают, правят и удаляют записи одного общего журнала. Токен — ключ доступа, не владелец записи.
- HTTP API на Hono и TypeScript. Контракт описан через OpenAPI и показан в Scalar.
- Токены выпускаются, показываются и отзываются только командами внутри контейнера приложения. В HTTP и MCP этих операций нет. OAuth нет.
- Те же операции журнала доступны через MCP.
- Журнал хранится в PostgreSQL через Drizzle. Адрес базы — `DATABASE_URL`: Postgres поднимается рядом в Compose либо указывается уже доступный URL.
- Одно развёртывание — один пользователь и одна база.

Вне этого среза: интерфейс журнала, учётные записи, справочник тегов, суммы и отчёты, другие провайдеры хранения.

## Capabilities

### New Capabilities

- `journal`: запись времени, открытый конец, параллельные записи, создание, чтение, правка и удаление
- `http-api`: HTTP-маршруты журнала, проверка входа, документ OpenAPI и справочник Scalar
- `access-tokens`: выпуск, список и отзыв токенов командами в контейнере; допуск запросов по bearer-токену
- `mcp`: те же операции журнала через MCP с тем же видом токена

### Modified Capabilities

- Нет. В `openspec/specs/` требований ещё нет.

## Impact

- Новый код сервиса на Node.js 24, TypeScript и Hono. Сейчас в репозитории только каркас коммитов и релизов.
- Зависимости: `@hono/zod-openapi`, `@hono/node-server`, `@scalar/hono-api-reference`, `drizzle-orm`, драйвер PostgreSQL, `drizzle-kit`, Zod.
- Схема PostgreSQL и миграции Drizzle. На старте приложение применяет миграции к базе из `DATABASE_URL`.
- Compose-файл для варианта «Postgres рядом» и переменная `DATABASE_URL` для внешнего адреса.
- Команды токенов выполняются через `docker exec` в контейнере приложения.
- Контракт HTTP и MCP не зависит от того, где запущен Postgres.
