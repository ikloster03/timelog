## ADDED Requirements

### Requirement: Команды токенов внутри контейнера

Система SHALL создавать, показывать и отзывать токены командами в контейнере приложения: `token create`, `token list` и `token revoke <id>`. Этих операций SHALL NOT быть среди маршрутов HTTP и инструментов MCP. Команды SHALL использовать базу из `DATABASE_URL` того же развёртывания.

#### Scenario: Создание из контейнера

- **WHEN** оператор выполняет `token create` внутри контейнера приложения
- **THEN** система создаёт токен в базе этого `DATABASE_URL`

#### Scenario: Нет HTTP-операции выпуска

- **WHEN** клиент ищет в документе OpenAPI выпуск, список или отзыв токена
- **THEN** таких операций в документе нет

### Requirement: Секрет показывается один раз

`token create` SHALL напечатать секрет и id токена. Система SHALL хранить для проверки хеш sha-256 секрета и префикс из первых 8 символов, а не сам секрет. Повторный запуск команды SHALL NOT напечатать секрет уже созданного токена.

#### Scenario: Выпуск

- **WHEN** оператор выполняет `token create`
- **THEN** вывод содержит новый секрет и id, а последующий `token list` показывает этот id и префикс без секрета

### Requirement: Список без секрета

`token list` SHALL показывать id, префикс, время создания и время отзыва каждого токена. Вывод SHALL NOT содержать секрет и SHALL NOT содержать хеш.

#### Scenario: Просмотр

- **WHEN** оператор выполняет `token list` после создания токена
- **THEN** система показывает id и префикс этого токена и не показывает секрет

### Requirement: Отзыв токена

`token revoke <id>` SHALL записать время отзыва. После отзыва этот секрет MUST NOT проходить проверку HTTP и MCP. Отзыв SHALL NOT удалять записи журнала. Повторный отзыв уже отозванного id SHALL завершаться отказом, не стирая прежнее время отзыва.

#### Scenario: Секрет перестаёт работать

- **WHEN** оператор отзывает id токена и клиент вызывает `GET /logs` с его секретом
- **THEN** система отвечает 401, а записи журнала остаются

#### Scenario: Неизвестный id

- **WHEN** оператор отзывает id, которого нет
- **THEN** система сообщает, что токена нет, и список токенов не меняется

### Requirement: Один вид токена для HTTP и MCP

Секрет, созданный командой `token create`, SHALL допускать и запросы `/logs`, и вызов MCP. Отдельного вида токена для MCP SHALL NOT быть.

#### Scenario: Тот же секрет в обоих входах

- **WHEN** клиент создаёт запись через `POST /logs` с секретом и затем читает открытые записи через MCP с тем же секретом
- **THEN** MCP возвращает эту запись
