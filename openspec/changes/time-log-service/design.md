## Context

Репозиторий содержит каркас Node.js 24: commitlint, хук коммитов и релиз через changelogen. Кода сервиса нет. Продукт — один общий журнал на одно развёртывание. Несколько клиентов ходят в него с приватным токеном. Своего интерфейса у журнала нет.

## Goals / Non-Goals

**Goals:**

- Записи с пустым концом и несколько одновременных открытых записей.
- Одни и те же операции журнала для HTTP и MCP.
- HTTP-контракт, который проверяется и публикуется как OpenAPI, и справочник Scalar поверх этого документа.
- Токены создаются, показываются и отзываются только из контейнера приложения.
- PostgreSQL через `DATABASE_URL`: база рядом в Compose или уже доступный адрес. Код один.
- Миграции применяются до приёма запросов.

**Non-Goals:**

- Интерфейс журнала, OAuth, учётные записи, справочник тегов, суммы и отчёты.
- Второй провайдер хранения. Drizzle закрыт интерфейсом журнала, чтобы его можно было заменить позже.
- Ключ идемпотентности у «начать». Повторный вызов создаёт вторую запись.
- Управление токенами в HTTP и MCP.

## Decisions

### Один процесс отдаёт и HTTP, и MCP

Приложение слушает один порт (`PORT`, по умолчанию 3000). Журнал — `/logs`. MCP — Streamable HTTP на `/mcp`. Справочник — `/scalar`.

Альтернатива: MCP по stdio рядом с редактором. Публичному сервису нужен сетевой вход, тот же токен и тот же контейнер.

### Операции журнала не знают про Hono и MCP

Модуль журнала принимает и возвращает записи. HTTP-маршруты и инструменты MCP вызывают его. Drizzle реализует хранение за этим модулем и не протекает в OpenAPI.

Поля записи:

| Поле | HTTP | PostgreSQL |
| --- | --- | --- |
| id | uuid-строка | `uuid`, ключ, генерирует база |
| start | ISO-8601 | `timestamptz`, обязателен |
| end | ISO-8601 или `null` | `timestamptz`, пустой значит «идёт» |
| name | непустая строка | `text`, обязателен |
| tags | массив строк | `text[]`, по умолчанию пустой |
| comment | строка или `null` | `text`, пустой допустим |

`timestamp` без пояса не используется: моменты лежат на абсолютной шкале.

Ограничения пересечений нет. Две записи с одним наименованием и пустым концом — норма.

Пропущенное `start` при создании и пропущенный конец при остановке берутся с часов сервера в момент запроса.

Список сортируется по `start`, затем по `id`. Запись попадает в период `[from, to)`, если `start < to` и (`end` пуст или `end > from`). Несколько параметров `tag` требуют, чтобы в массиве была каждая из этих строк. Регистр и повторы внутри массива сохраняются.

`PATCH`: нет поля — значение не меняется; `end: null` снова открывает запись; момент в `end` закрывает её. Конец раньше начала отклоняется.

### Контракт HTTP пишется один раз

Маршруты — `OpenAPIHono` и Zod из `@hono/zod-openapi`. Схема записи одновременно проверяет тело и попадает в документ. Scalar подключается через `@scalar/hono-api-reference`, `Scalar.serve`: справочник на `/scalar`, документ на `/scalar/openapi.json`.

Альтернатива: `hono-openapi` и описание маршрута сбоку от обработчика. Для нового контракта схема и документ тогда легче разъедутся.

Схема безопасности документа — `http` bearer. Ею закрыты операции `/logs`. `/scalar`, документ OpenAPI и `GET /health` открыты. `/health` отвечает 200, когда процесс уже слушает порт.

Ошибки журнала — JSON `{ "error": string }`: 400 на неверное тело, 401 на токен, 404 на неизвестный id. Удаление существующей записи — 204.

### Токен — секрет один раз, дальше только хеш

Команда `token create` печатает секрет один раз. В базе лежит sha-256 и префикс из первых 8 символов, плюс id, время создания и время отзыва. `token list` показывает id, префикс, создание и отзыв, без секрета. `token revoke <id>` ставит время отзыва.

Проверка запроса ищет хеш и пустое время отзыва. Неизвестный и отозванный токен дают один и тот же отказ.

Команды — отдельная точка входа того же образа: `node dist/cli.js token list|create|revoke`. HTTP-маршрутов у них нет. CLI использует тот же `DATABASE_URL`.

Альтернатива: хранить секрет в открытом виде. Тогда список токенов в выводе `docker exec` равен полному доступу.

### База задаётся только адресом

`DATABASE_URL` обязателен. Рядом — `docker-compose.yml`: сервис `db` (PostgreSQL, том для данных) и сервис `app` с URL на `db`. Внешний адрес — тот же образ без сервиса `db`.

Схема Drizzle в репозитории. `drizzle-kit generate` пишет SQL в репозиторий. При старте `migrate` применяет непрогнанные миграции, и только после этого процесс слушает порт. Роли в URL нужны права менять схему.

Альтернатива: Postgres в том же контейнере, что и Node. Адрес снаружи и база рядом тогда стали бы двумя способами запуска, а том и процесс базы смешались бы с приложением.

### Сборка

TypeScript собирается в `dist/`. Образ содержит эту сборку и миграции. `prepare` и commitlint остаются как есть.

Раскладка исходников:

- `src/journal` — операции и типы записи
- `src/db` — схема Drizzle, клиент, миграция
- `src/http` — маршруты, Scalar, проверка токена
- `src/mcp` — инструменты поверх тех же операций
- `src/tokens` — хеш, проверка, команды
- `src/main.ts` — миграция и сервер
- `src/cli.ts` — команды токенов

Пакет MCP — официальный SDK с транспортом Streamable HTTP, смонтированный на Hono.

## Risks / Trade-offs

- [Повтор «начать» из-за обрыва агента создаёт вторую открытую запись] → В этом срезе это принятое поведение. Клиент различает записи по id. Ключ идемпотентности не добавляется.
- [Забытый пустой конец висит, пока его не закроют] → `GET /logs?open=true` и инструмент открытых записей показывают их. Автозакрытия нет.
- [Миграции при старте требуют права DDL] → Для внешнего URL это условие доступа. При ошибке миграции процесс выходит и не слушает порт.
- [Справочник открыт без токена] → Он показывает форму маршрутов, не записи. Вызов из Scalar к `/logs` уже требует bearer.
- [Один журнал на все токены] → Отзыв токена отнимает доступ, не отделяет данные. Для одного пользователя этого достаточно.

## Migration Plan

Данных сервиса ещё нет, переносить нечего.

1. Собрать образ.
2. Задать `DATABASE_URL`: Compose с сервисом `db` либо внешний адрес.
3. Запустить контейнер. Миграции проходят до порта.
4. `docker exec` → `token create`. Секрет попадает в клиент HTTP или MCP.

Откат: остановить контейнер приложения. База и том остаются. Повторный старт снова применяет только новые миграции.
